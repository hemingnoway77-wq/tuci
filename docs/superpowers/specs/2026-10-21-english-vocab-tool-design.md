# 英语单词收集器：首版设计规格

日期：2026-10-21

状态：用户已确认规格与计划并选择直接实现；首版已实现，通过本地测试、真实窗口模拟接口验收与 exe 启动验证。

目标平台：Windows x64 桌面，交付可双击运行的 `.exe`。

## 1. 目的与已确认需求

用户在上网时遇到陌生英语单词，将其粘贴到一个简单的桌面工具中。工具调用用户配置的 AI API，按固定模板生成 Markdown，存入预设文件夹，供 Obsidian 复习。可按词性分目录，并与已经保存的历史单词建立内部链接。

用户已明确选择：

- OpenAI 兼容接口，配置 API 地址、API Key、模型名。
- 精简学习模板：音标、中文释义、词性、双语例句、常见搭配、已有词条关联。
- 主界面只有单词、可选原句、解析并保存，以及结果与保存位置。
- 一词一份笔记，多种词性在同一笔记内；可按主要词性归档。
- 重复收录提示打开已有文件，不覆盖用户手写内容。
- AI 候选关联必须与本地现有词条匹配后才能生成链接。

成功标准：首次配置后，用户粘贴一个词并点击一次按钮，成功时得到一份格式一致、Obsidian 可直接使用的笔记；失败时看到明确原因，输入保留，目标目录没有残缺笔记。

## 2. 实现方案与范围

采用 C#、.NET 10 和 WPF，构建原生 Windows 程序。选择依据是本任务只要求 Windows、直接读写本地文件，且当前机器已经具备 .NET 10 SDK。网页套壳亦可实现，但当前无需引入浏览器运行环境和前后端通信。Python 打包亦可实现，本次不采用。

首版交付 Windows x64 的自包含单文件 exe、源码、构建脚本和中文使用说明。程序运行不要求用户额外安装 Python、Node.js 或 .NET；实际文件体积以发布产物为准。无需管理员权限。运行所需的原生库可由 .NET 自动解包到当前用户的临时目录。

首版不增加全局快捷键、剪贴板自动监控、浏览器扩展、批量导入、发音音频、复习计划、云端账户或 Obsidian 插件。复习和知识图谱由 Obsidian 完成。

## 3. 界面与交互

### 主窗口

- 单词输入框：一次处理一个单词。
- 原句输入框：选填，帮助判断具体词义和主要词性。
- “解析并保存”按钮：生成并成功校验后自动保存，不要求逐词再次确认。
- 状态区域：区分校验、调用 AI、保存、完成、失败；处理时禁止重复提交，并允许取消。
- 结果区域：显示生成的 Markdown 文本、文件路径；提供“打开笔记”和“打开所在文件夹”。
- 设置入口。

配置未完成时指出缺少的字段。输入无效时在调用 AI 前提示。已经收录的词直接展示已有路径并允许打开，避免无意义调用；AI 调用结束时再次检查文件是否已存在，避免并发覆盖。

“打开笔记”使用经过 URL 编码的 Obsidian open URI；未安装或无法唤起时说明可在 Obsidian 中打开已保存文件。“打开所在文件夹”通过 Windows 资源管理器完成。

### 设置窗口

- API Base URL、API Key、模型名。
- Obsidian 仓库根目录：通过文件夹选择器选择。
- 单词输出子目录：相对于仓库根目录，默认 `英语单词`。
- “按词性分文件夹”开关，默认开启。
- 保存设置。

输出目录必须位于所选仓库内，不允许绝对路径、`..` 越界或借助子目录链接跳出仓库。程序不要求仓库已安装任何额外插件。

实施细化：单词输出子目录的路径段除 Windows 非法字符外，还拒绝会干扰 Wikilink 的 `#^[]|`，并给出可修改的中文提示。仓库根目录可包含这些 Windows 允许的字符，外部打开 URI 会正确编码；历史子目录中的危险路径仍参与查重，但不生成关联链接。

API Key 默认遮挡，使用 Windows 当前用户的 DPAPI 加密后保存在用户本地应用数据目录。其余设置也保存在该处，不写入 Obsidian 仓库，不要求在 exe 目录写文件。设置保存后重启仍有效；Key 解密失败时要求重新填写。

## 4. 单词身份与归档

输入去掉首尾空白、统一英文大小写与撇号形式，接受英文字母及单词内部的连字符、撇号，长度限制为 64 个字符。拒绝句子、路径字符、空值和控制字符。原句最多 2,000 字符。

首版以规范化后的实际输入作为词条身份与文件名，不自动把 `running` 合并为 `run`，不把 `saw` 合并为 `see`，也不静默纠正拼写，避免误合并不同词义。AI 如判定不是有效英语词，返回可读提示并停止保存。

例：`Resilient` 保存为 `resilient.md`。同一个词的各词性均写在此文件中。

实施细化：Windows 保留设备名是文件名的唯一例外，`con/aux/prn/nul` 使用 `_con.md/_aux.md/_prn.md/_nul.md`，索引按明确规则还原原词，词条身份不变。

开启分类时，AI 根据原句选择主要词性；没有原句时选择常见主要词性。主要词性必须属于返回的词性集合。代码使用固定映射生成目录，不接受 AI 返回的目录或文件路径：

| 词性 | 目录 |
| --- | --- |
| noun | 名词 |
| verb | 动词 |
| adjective | 形容词 |
| adverb | 副词 |
| pronoun | 代词 |
| preposition | 介词 |
| conjunction | 连词 |
| interjection | 感叹词 |
| determiner | 限定词 |
| numeral | 数词 |
| other | 其他 |

关闭分类则直接存入单词输出子目录。重复检测覆盖该词库子目录的全部普通子目录，不受当前分类开关影响。若已经存在多个同名词条，列出已有路径供用户打开，本次不生成新文件。已经存在的笔记不因词性变化或开关切换被移动或重写；需要整理时用户可在 Obsidian 内处理。

## 5. 固定 Markdown 格式

AI 返回结构化数据；程序按内置模板渲染 Markdown，不把 AI 的自由格式全文直接写盘。首版不提供模板编辑器。

示例中的 `resilience` 仅在它确实是词库内唯一匹配的已有笔记时生成链接。实际没有匹配时显示“暂无已收录的关联词”。

```markdown
---
type: english-word
word: resilient
primary_pos: adjective
parts_of_speech:
  - adjective
created: '2026-10-21T15:00:00+08:00'
tags:
  - english
  - vocabulary
---

# resilient

## 音标
- 英：/rɪˈzɪliənt/
- 美：/rɪˈzɪliənt/

## 词性与释义
- **形容词**：有韧性的；能迅速恢复的。

## 例句
1. She remained resilient after the setback.
   遭遇挫折后，她依然坚韧。
2. The local economy proved resilient.
   当地经济展现了韧性。

## 常见搭配
- a resilient economy：韧性强的经济体
- resilient communities：具有韧性的社区

## 遇见时的原句
未提供。

## 已收录的关联词
- 同根词：[[英语单词/名词/resilience|resilience]]

## 我的笔记
```

内容目标是 1–3 个常见释义、2 个双语例句、2–4 个常见搭配；给出原句时优先解释其中的用法。若某口音音标无法可靠提供，写“未提供”，不伪造值。其他必需字段为空或类型不符时不落盘，并说明返回内容不完整。

YAML 字段正确转义；文本内容按模板安全渲染，AI 字符串中的标题、内部链接、HTML 或代码围栏不能破坏固定结构或偷偷创建链接。原句作为纯文本保留。输出为 UTF-8、LF 换行。

## 6. 历史词条与关联

- 只扫描用户设置的单词输出子目录下的 `.md`，不读取整个仓库的学习笔记正文。
- 首版按 Markdown 文件名（去扩展名、忽略大小写）识别历史单词；不解析任意旧笔记的别名、全文或语义索引。
- AI 产生最多 12 个候选，关系类型限定为同根词、近义词、反义词、易混词；程序在本地做精确匹配，最终最多展示 8 个。
- 仅保留存在、唯一匹配且不是当前词条的目标；同名文件有多个时跳过，不任意选择。
- 链接一律由本地实际路径生成，如 `[[英语单词/名词/record|record]]`，采用仓库相对路径、正斜杠、无 `.md` 扩展名。
- AI 提示词不包含仓库路径、API Key 或历史笔记正文；一次解析的消息仅包含单词、可选原句和固定任务要求。Key 仅用于用户指定服务商的 HTTP 鉴权。
- 不要求为旧笔记补写反向链接。新笔记的有效内部链接可由 Obsidian 自动展示为旧笔记的反向链接。

这一设计提供候选匹配，不保证发现所有语义相关历史词；首次使用时关联区域为空属于正常结果。原有笔记被用户在工具外重命名或移动后，链接维护遵循 Obsidian 自身的操作与设置。

## 7. AI 调用与失败处理

通过常见的 Chat Completions 协议调用 OpenAI 兼容服务：`Authorization: Bearer <key>`，请求包含配置的 `model` 和消息。Base URL 支持服务商提供的 API 前缀（如 `https://example.com/v1`）；拼接一次 `/chat/completions`，也允许直接填写已包含此后缀的完整地址。不会自动猜测或追加 `/v1`。

默认要求 HTTPS；本机开发服务允许 loopback HTTP。调用超时 90 秒。支持用户取消，不做可能重复计费的自动重试。兼容层首版使用非流式请求，不强制供应商支持 JSON Schema 或 `response_format`。以清晰提示词约束 JSON，并允许剥离单层 JSON 代码围栏；其余格式错误明确报错，不猜测补齐。

返回数据包括：有效词标记、解释性错误、英美音标、主要词性、各词性及中文释义、例句及翻译、搭配及翻译、候选关联词及关系类型。模型返回的词不能改变输入身份、写入目录或目标文件名。

对鉴权失败、模型不存在、限流、网络错误、超时、空结果和格式不合规分别显示中文提示。错误展示不得泄漏 Key，不直接显示可能含凭据的请求头或完整原始服务器响应。取消或失败后保留当前输入。

## 8. 本地存储可靠性

保存前完成全部数据校验和 Markdown 渲染。目标路径仅由已校验的仓库、输出子目录、固定词性目录与规范化单词构成。

写入同目录临时文件，再以不覆盖的原子移动方式提交为 `.md`。已存在文件、目录无权限、磁盘故障或目标目录变化时不覆盖、不留下半份正式笔记，尽可能清理本次临时文件。失败的生成结果仍显示在窗口中以便手动复制或重试。

生成过程中捕获设置快照，禁止修改设置影响正在进行的请求。UI 不被网络调用或目录扫描阻塞。读取索引前以及实际保存前均校验路径，跳过或拒绝跨出所选根目录的目录链接。

## 9. 模块边界

- **桌面界面**：输入、状态、设置与结果展示；只调用应用服务。
- **配置服务**：持久化普通设置和 Windows 加密 Key。
- **AI 客户端**：组装请求、调用兼容接口、解析并校验数据；允许注入 HTTP 客户端用于测试。
- **词库服务**：输入规范化、扫描词库、重复词检查、关联目标解析。
- **模板与写入服务**：Markdown 渲染、固定目录映射、安全路径与原子落盘。
- **应用服务**：组织上述流程、取消与错误映射；不把界面逻辑嵌入文件或 HTTP 模块。

不引入数据库、后台服务或独立本地 HTTP 服务器。文件系统中的 Markdown 是词库的真实数据来源。

## 10. 验证与验收

自动验证聚焦真实边界：输入与路径约束、多词性分类、跨目录重复词、唯一与歧义链接、YAML/Markdown 转义、API 正常及异常返回、取消、禁止覆盖、写入失败不留残缺文件。使用临时仓库和本地模拟 HTTP 服务，不依赖用户 Key，不消耗用户的真实 API 额度。

发布前必须完成：

1. 核心测试通过，Release 编译成功。
2. 生成自包含 Windows x64 单文件 exe。
3. 实际启动发布后的 exe，验证窗口和设置持久化，模拟 API 完成“输入 → 调用 → 保存 → 链接”全过程。
4. 验证错误 Key、格式错误与重复词不会覆盖历史文件；结果文件可被标准 Markdown/YAML 读取，Obsidian 链接采用有效的仓库相对路径。
5. 提供中文说明，包含配置示例、分类规则、旧词条按文件名识别的约束、exe 路径与构建方式。

用户尚未提供真实 API 配置，因此真实供应商的联网验收在用户本地填入配置后进行；交付时明确区分模拟接口验证与真实供应商验证。
