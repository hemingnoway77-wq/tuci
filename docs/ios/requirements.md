# 兔词 iPhone 版需求

2026-11-05。本文记录已确认的使用方式，供设计和验收使用。Windows 的行为基线见[项目说明](../../README.md)，平台目录和开发分支约定见[交接文档](../handoffs/2026-11-05-ios-handoff.md)。

## 手机端的学习流程

- 现有 Windows 功能均需适配，包括单词与可选原句收录、自配 AI、拼写判断、重复词保护、笔记生成和关联、主题、每日文章推荐与缓存。平台专用操作按其在手机上的实际用途适配。沿用兔词的纸页阅读风格，按竖屏、系统字号和单手操作重新排版。
- 从每日阅读打开文章后，在兔词内查看来源网站的原文。返回时保留文章列表和阅读入口。
- 在应用内浏览笔记目录，打开笔记，并能从正文查看或访问关联词条。沿用已有 Markdown 笔记、目录与词条链接，包括带显示文字的 Wikilink。

## 词条交互与验收

对一个指向已有笔记的词条，单击弹出简要卡片，阅读位置保持在当前笔记。双击直接打开目标笔记。这两个动作互斥。

以仓库中的 [introduced 示例笔记](../examples/introduced.md)为例，当词库中存在链接目标 policy 时，单击例句里的 policy 应显示简卡，双击应直接跳到 policy 的完整笔记，过程中不能闪现简卡，也不能重复打开笔记。建议以词条名、音标和主要中文释义作为简卡的初始内容，并提供可直接打开完整笔记的按钮，方便单手和辅助功能操作。返回原笔记应恢复原阅读位置。

## 漫游复习

在词库里按权重随机展示单词。用户可以标记“今天已记住”，也可以不标记而翻到下一张。同一天内，两种情况下都可能再次抽中该词。在其他条件相同的情况下，标记记住的词再次被抽中的概率更低。当天展示中，点击记住的比例越低，权重越大。

加入词库的时间影响新词加分，距上次展示的时间独立影响复习优先级。验收时要分别比较其他条件相同的新旧词、久未展示与刚展示的词、今天多次略过与多次记住的词。还要验证一条很早加入且长期未出现的词能够重新获得较高权重。

建议仅在漫游卡片实际展示时更新“上次出现”。每张卡片的一次明确操作只记一次，预加载、重绘和切回前台均不增加次数。具体系数和当天统计方式在实现前用样例验证。

## 同步范围

首阶段供本人和少量朋友使用，每人拥有独立词库。使用用户已有的阿里云服务器让同一个人的 Windows 和 iPhone 自动同步目录、词条和笔记，两端可在不同网络和不同时间上线。已有 Windows 笔记与个人补充内容需要完整保留。验收覆盖两端新增、修改、离线后重新连接、跨用户隔离，以及双方改动同一笔记时保留内容。具体设计见 [iPhone 与同步服务设计](design.md)。
