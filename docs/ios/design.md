# 兔词 iPhone 与同步服务设计

设计草案 · 2026-11-05 · 开发分支 `feature/ios`

用户已确定 iPhone 功能、词条手势、复习偏好、独立词库和阿里云同步。下文提出客户端技术、配对方式、冲突处理和复习系数，供实现前审阅。[已确认需求](requirements.md)

## 一次学习过程

1. 在“阅读”看到当天推荐，点文章进入应用内原文页，返回时回到同一列表位置。推荐沿用 Windows 的来源、日期、手动刷新和摘要缓存规则。离线时显示缓存摘要，打开在线原文失败时可重试。
2. 在“收录”输入英文单词和可选原句，使用个人配置的 AI 生成卡片。已有词直接打开。保存后即可在手机查看，本地新增会排队等待同步。
3. 在“词库”按原目录打开笔记。正文里单击关联词只展示简卡，双击直接打开对应笔记。两种手势互斥，返回恢复原笔记及位置。简卡建议展示词、音标、主要义项，另提供“打开笔记”按钮与辅助功能操作。遇到有多个候选的旧链接时提供选择。
4. 从词库进入“漫游”。每次看一张词卡，可点“今天已记住”或直接翻过。下次用 Windows 打开同一词库时，能看到手机新增的笔记并继续在 Obsidian 阅读。

手机端建议使用原生 SwiftUI。收录、阅读、词库作为底部三个入口，漫游从词库进入。正文采用 Windows 版已有的纸页配色与英文衬线风格，适配系统字号、窄屏、深浅背景下的文字对比和单手点击。工程和品牌资源置于 `ios/`，Windows 的同步入口集成到现有 WPF 应用。

## 词条身份与文件

持久化内容采用 UTF-8 Markdown 和词库内的相对路径。两端本地保有完整笔记。iPhone 的目录、简卡和关联索引可以从本地 Markdown 重建，用户编写的内容与未知段落原样保存。可识别的单词笔记参加漫游，词根和普通说明笔记可通过目录及链接阅读。单词身份遵循 Windows 的大小写、撇号、连字符和词形规则。

以既有 Windows 示例与测试作为行为基线，覆盖正常收录、纠错、取消、已收录词、同名歧义、根词链接、补链及人工修改保护。移植 Chat Completions 地址处理、流式及普通响应、超时取消、字段校验与脱敏诊断。手机使用 Keychain 保存 API Key，请求由用户设备直接发送给配置的 AI 服务商。推荐与漫游在设备上运行。[Windows 行为说明](../../README.md)

## 云端与设备配对

用户选用了阿里云中转，方便电脑关机后手机仍能提交改动。局域网直连需要两端同时在线，共享云盘目录则依赖各端文件同步器处理冲突。建议使用一个轻量 ASP.NET Core 服务和 SQLite，将服务端源码放在 `server/`。每个用户独享一个词库，服务端只向已配对的设备提供该用户的数据。

建议采用邀请制。管理员为每人创建独立词库和一次性激活凭证。首台设备激活后，可以生成短期单次配对码供另一台设备输入。设备通过 HTTPS 交换各自的随机令牌。凭证和配对码以摘要保存，兑换操作原子完成，限制猜测次数。管理员可单独撤销丢失设备，或为原词库重新签发激活凭证。服务端从设备身份确定词库边界，读取、写入、冲突和增量查询都执行相同隔离。

## 自动同步和冲突

- 同步用户选定的词库目录、Markdown 笔记与相对层级。设备端 AI 凭证、阅读缓存、日志、文件锁、备份和本机索引保存在各自设备。词库内 Markdown 的链接保留原文，客户端存储该词库相对原 Obsidian 仓库的位置，兼容相对于上层仓库根目录或单词目录本身的 Wikilink 写法。普通笔记即使使用中文文件名，也要同步并可在目录中阅读。
- 两端在启动、恢复前台、本地保存后以及在线使用期间定期同步。Windows 同时监听 Obsidian 等外部编辑并定期重新核对目录。后台调度取决于操作系统，手机离线保存的改动会在下次可用时传送。
- 每个词库维护服务器递增游标，每条笔记有稳定 ID、相对路径、正文和版本。操作携带唯一操作 ID 和客户端已知版本。服务器事务内记录版本、操作结果与变更序号，接到重试时返回原结果。客户端持久化待发操作，只有本地安全应用完一页变更后才推进游标。
- 首次关联已有目录先比对双方清单。相同路径与内容合并索引，单侧内容补到另一侧。相同路径但内容不同，保留两份并显示冲突。设备第一次上线或本地目录读取失败时，不能将“未读到”当成删除。
- 对同一版本的并发修改保留两份内容，显示可辨识的冲突副本。移动通过稳定 ID 传递。无法确定文件身份时按新建及有记录的删除处理。删除使用带版本的删除记录。离线修改遇到远端删除时保留该修改供恢复。所有落盘路径都检查越界、保留目录、符号链接、大小写碰撞与目标平台非法文件名。
- Windows 导入在现有词库写锁内重新核对磁盘内容，暂存后原子替换。笔记版本可附带程序上次生成的分区校验值，仅合并本条笔记的有效记录。同步接收方使用原校验值识别人工修改，不得用接收到的正文重新登记可改写区域。缺少登记的手写笔记按普通笔记导入。区分来自同步的落盘和新的本地修改，避免相同内容反复上传。
- 阿里云部署交付包括 HTTPS 入口配置示例、持久数据目录、邀请及撤销命令、数据库一致性备份与恢复步骤。先在隔离词库验证 Windows 和 iPhone 往返，再接入用户现有词库。

## 漫游权重

建议用以下规则作为第一组可调整的系数。抽取概率等于某词权重除以全部可漫游词的权重之和。

    权重 = 0.5 + 3 × ln(1 + 间隔天数) + exp(−入库天数 / 3)
               + 2 × (1 − 当天记住比例) + min(当天未标记翻过次数, 3) / 3

间隔取上次实际展示至今的天数，从未展示时从加入时间计算。入库时间优先取笔记的有效创建字段，其次取已保存的本地文件创建时间，导入后保持稳定。预加载和普通目录阅读均不改变漫游记录。每天按设备本地日期统计，跨日保留入库时间与上次展示时间。

每次实际展示产生独立记录。点“今天已记住”即记录一次并进入下一张；直接翻过记录一次未标记。中断会话只保留展示时间。当天再次抽到可显示“今天记住过”，用户仍可就本次作答。建议以（当天记住次数 + 1）÷（当天已完成展示次数 + 2）平滑记住比例。复习记录保存在手机，本方案建议首版云同步范围为词库与笔记。

例如两个词同样刚出现且入库时间相同，今天各完成一次展示，未标记翻过的词比点了记住的词权重高 1。一个入库很久且 30 天未出现的词，光是间隔项就获得约 10.30 分，足以超过新词最多 1 分的入库加分。基础分始终为正，记住后仍可在当天抽到。

## 开发与验收顺序

1. **本地词库与阅读**　用仓库示例在 iPhone 上验证目录、简卡、双击跳转、返回位置、漫游统计与抽取概率。在小屏和大字号下检查阅读布局。
2. **Windows 功能适配**　对照既有用例测试收录与笔记保护，测试每日推荐缓存、应用内原文和三套主题。AI 测试使用模拟接口。
3. **跨端同步**　先用两个测试用户和模拟设备验证隔离、配对、重试、并发修改、删除后的离线修改、目录变化及备份恢复，再由真实 Windows 客户端与 iPhone 互测。
4. **真机交付**　使用完整 Xcode 构建并安装到测试机，检查原文阅读、触控、切后台、断网与重连。在测试词库完成部署验收后再接正式数据。

当前 Mac 已发现 Swift 工具链，完整 Xcode 和真机验证待准备。部署前核实阿里云主机系统、现有 HTTPS 入口及可用持久目录。服务器凭据由部署环境提供。
