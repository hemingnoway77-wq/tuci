# 2026-10-28 同次请求纠错与笔记整理

用户希望新输入的拼错单词能够同时修正，且不增加等待。保留现有 WPF、粉色界面、原生阅读预览、文件模板和本地关联流程。

## 行为

- 同一次请求返回拼写判断与针对最终单词的完整解析，不增加检查请求、联网词典或纠错自动重试。
- 明确且唯一的近距离错拼，自动使用修正后的表面词形保存。标题、文件名、例句、历史索引、关联身份与返回词一致；状态栏和词卡显示“原输入 → 修正后”。属性保留 `original_input`，来源原句保留原文。
- 合法词形继续独立收录。原形和时态关系不等同于拼写修正；本地保护规则涵盖动词、名词及形容词比较级／最高级。
- 不确定或无效时不保存，展示最多三个候选，保留输入。修正目标已有卡片时返回已有路径，不创建错拼文件或覆盖个人内容；仍在原有写锁内复查。
- 已有输入词条继续零 API 返回，不批量重写旧词卡。取消或失败时输入不自动替换，成功和已收录时才更新输入框。

## 协议与本地检查

新增 `spelling`，包含 `input_word`、`word`、`status`、`suggestions`。四种状态为 valid、corrected、uncertain、invalid。生产调用将原输入传入解析器，绑定校验输入回显、有效标志、状态、目标词、候选及两个例句。成功响应缺少拼写判断即拒绝保存；旧的无效词拒绝响应可以安全保留。

近距离限制按输入长度为 1／2／3 次编辑，支持相邻字母转置。规则用于阻止明显不相关的替换，不作为词典。目标为原形时阻止把合法屈折形式改写为原形；反向词形保护只在返回 lemma 明确等于输入时启用，避免把 `frien → friend` 这种漏字误当作“加 d 形成时态”。词义及拼写分类仍由用户配置的模型负责，不能保证所有语境下都正确。
