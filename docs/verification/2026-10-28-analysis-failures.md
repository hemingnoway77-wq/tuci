# Credit / produce 生成失败诊断与修复

日期：2026-10-28。基线：0057db9（双主题版）。

## 证据与结论边界

用户描述 Credit 和 produce 经常收到“AI 返回的解析内容不完整或格式不合规”，要求查看最近日志。

检查当前用户 LocalAppData/Roaming 的 VocabCollector 目录、运行 exe 所在分发目录及源码后确认：旧版本没有持久化失败日志，也没有保存原始模型失败响应。当前窗口已经是 debate 成功状态，不能还原历史提示。没有把推测当作历史根因。

对当前配置服务进行了两个受控请求（credit、produce 各一次；原句为空），不向用户词库写入文件：

- credit：返回符合既有约束，接受。大小写已规范化，Credit 首字母大写不是独立拒绝原因。
- produce：字段形状、3个义项、2个例句等正常；第1句为 `This farm produces fresh fruit and vegetables.`，第2句含原形 `produce`。旧校验要求每句出现完全相同的目标词，故第1句正常三单 `produces` 被误拒，得到“拼写判断与解析不一致”。这与用户回忆的通用格式提示属于不同分支，不混为同一历史故障。

捕获内容只含公共单词模型解析，已去除 Key；没有保存请求头或私人原句。回放文件在忽略提交的 `.artifacts/analysis-repro/20261028-172159/`。

## 修复

1. 新增共用 WordForms：仅在目标词等于可靠 lemma 且解析含动词义项时接受保守三单 s/es/辅音 y→ies。例句校验和 Markdown 加粗复用同一完整 token 匹配；保留产生词形的英文原文，卡片词、文件名、标题不变。未开放过去式、-ing、名词复数或不规则推导，派生/复合词继续拒绝；拼写纠正及正确输入词形保护不变。
2. AnalysisJson 保留原类型、数量、枚举及安全限制，失败时提供具体中文说明和稳定诊断 code/path/rule/count。路径来自固定 schema 字段及数组数字，不含模型提供的原值。关联词数量给出完整数组的实际总数；拼写一致性异常仍沿原分支。
3. Analyzer 仅失败时记录最小本地元信息：时间、归一化输入词、错误代码、字段路径、约束与数量。App 注入 LocalAppData/VocabCollector/logs 文件 sink；不记录 API Key、请求头、来源原句或模型全文，成功零文件 IO。不新增 AI 调用或自动重试，日志不可写不掩盖原错误。
4. 日志为按日 JSONL，单文件256 KiB后保留一个轮转副本，清理较旧的精确日志文件名。不会删除相似名称的个人文件。

Credit 历史格式失败仍未定位。新的字段诊断让以后可区分释义数量、音标类型、词根结构等实际原因；没有为通过未知响应而盲目放宽校验。
