# 2026-11-07 iPhone 登录与手机交互修订验收

## 登录来源

页面原先的 `no-referrer` 策略与 `mode: same-origin` 请求组合，会按 [Fetch 标准 §3.2](https://fetch.spec.whatwg.org/#append-a-request-origin-header) 将 POST 的 Origin 置为 `null`，与服务端校验冲突。

- 账号及同步请求显式使用 `referrerPolicy: same-origin`；HTML 与 Nginx 的对应策略同步调整。外部 AI 请求继续省略凭据和 Referrer。
- 服务端仅为 `Origin: null` 且浏览器 Fetch Metadata 为 `Sec-Fetch-Site: same-origin` 的旧缓存请求提供兼容。单独 null、不明来源、same-site、cross-site 和恶意 Origin 仍拒绝。
- 新 HTTP 回归在修复前返回 403，修复后返回 200。账号服务测试、旧同步协议集成及 Windows Core → 网页 cookie/IndexedDB → Windows Core 往返均通过。
- 公网 HTTPS 分别验证当前策略和旧缓存策略，登录及 cookie 会话均成功；四类恶意/不明来源均 403。验证设备已退出撤销，未改动笔记。
