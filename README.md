# 兔词

一个简单的 Windows 桌面工具：粘贴陌生英文单词，调用自己配置的 AI，生成固定格式的 Markdown，存入 Obsidian 仓库。

## 开始使用

1. 双击 `dist/win-x64/兔词.exe`。发布版自带运行环境，无需另装 .NET、Python 或 Node.js。
2. 点击右上角“设置”，填写 API 地址、API Key、模型名。
3. 选择 **Obsidian 仓库根目录**，填写仓库内的单词子目录，默认 `英语单词`。
4. 按需开启“按主要词性分文件夹”，保存设置。
5. 粘贴一个单词；可附上遇见它时的原句。点击“解析并保存”。
6. 完成后直接阅读排版好的笔记预览，可选择复制文字、点击词条和词根链接，或点击“在 Obsidian 中打开”。

## 界面与阅读预览

界面采用纸页式排版：米色桌面、纸白卡片、发丝线分区，英文词条和文章标题保留衬线字体；小型中文标签、按钮、路径、日期与说明使用微软雅黑界面字体，词卡正文使用 Segoe UI 并显式回退到微软雅黑。辅助文字至少 12 DIP，说明与按钮 13 DIP，输入和正文 14 DIP，保留布局取整与 Display 格式化，并启用 ClearType。主窗口顶部是「收录 / 每日阅读」两个页面，右上角的三枚主题色点提供三套配色：**墨白**（纯黑白灰）、**暖灰**（纸页米色、酒红强调，默认）和**玫红**（浅粉纸面、玫瑰强调），悬停可看到名称。

切换立即应用到主窗口、已打开的设置页、每日阅读页、已显示的笔记和滚动条，保留当前输入和阅读内容，不调用 AI。窗口标题栏（拖拽条）也跟随主题使用纸色底、墨色文字，不再是系统强调色。主题选择单独保存在 `%LOCALAPPDATA%\VocabCollector\appearance.json`，不需要先填写 API 或 Obsidian 配置，重启后继续使用；缺失或损坏时使用暖灰。保存偏好失败时仍可使用当前主题，并显示提示。

图标采用用户最终确认的透明黑色兔耳放大镜：黑色轮廓，外围及镜圈内部保留真实透明通道。exe、窗口标题栏、任务栏和界面左上角品牌标记统一使用同一图标；提供 16–256 像素的多尺寸版本。验收见[图标与字体清晰度验证记录](docs/verification/2026-11-04-icon-and-legibility.md)，原界面改版见[书页界面验证记录](docs/verification/2026-11-04-literary-redesign.md)。

预览使用本地原生文档排版：隐藏 YAML 属性、Markdown 格式符号和程序注释，展示标题、分行释义、加粗、引用、列表及词条关联。选择复制获得阅读文字；磁盘保存的文件仍是原来的 Markdown。历史词条和词根链接可点击在 Obsidian 中打开，普通 HTTP/HTTPS 链接使用默认浏览器。

滚动条闲置时隐藏，滚动、拖动或鼠标移到滚动条区域时显示；停止后约一秒隐藏。原句、设置、预览和词条列表使用同一套滚动样式。窗口最小为 920×660，较小窗口内可滚动查看输入与笔记。

阅读预览不需要 WebView 或浏览器组件，也不加载笔记中的远程图片。Markdown 解析使用 Markdig，许可证随发布附带并嵌入程序。实现与验收见[粉色界面验证记录](docs/verification/2026-10-22-pink-interface.md)。

可执行文件可以单独复制到别处运行。设置位于 `%LOCALAPPDATA%\VocabCollector\settings.json`，API Key 使用当前 Windows 用户的 DPAPI 加密，不以明文保存。把此配置文件复制到其他电脑或其他 Windows 账户后，需要重新填写 Key。

## 每日阅读

点击主窗口顶部的「每日阅读」，即可在同一窗口内看到最多两篇通用英文泛读和一篇技术文章。每篇文章展示英文标题、摘要、来源及可用的发布日期，点击“阅读原文”使用默认浏览器打开来源网站。无需配置 API Key 或 Obsidian；整理单词时也可以暂时切到阅读页。

文章来自公开订阅源：ScienceDaily 社会／环境、Cloudflare 技术博客和 BBC Technology。它们是泛读材料，不是考研真题或配套试题。订阅源只提供摘要和原文入口，本工具不抓取全文或生成中文翻译。

同一天重开优先使用当日缓存，跨日获取来源并尽量轮换推荐；“刷新文章”可手动重新获取。日期按电脑本地日期计算；关闭程序后不在后台推送。切换到其他页面会取消正在进行的获取，已经加载的文章会保留，返回后继续阅读。网络不通时保留上次缓存并说明状态，首次使用且无缓存时可重试。文章的发布日期和当天推荐日期分别显示，不把旧文章标为新发布。

**每日阅读额外 AI token 为 0。** 获取文章、每日选择和缓存不调用模型，不读取或匹配本地单词库，也不写入 Obsidian。打开来源网页只涉及该网站自身的访问。阅读缓存独立保存在 `%LOCALAPPDATA%\VocabCollector\reading`，不包含 API Key。离开阅读页会取消正在进行的获取。

如需收录文章里的生词，仍可回到原有输入框粘贴单词与原句，由你主动点击“解析并保存”；该操作沿用原有 AI 配置和收费方式。实现与验收见[每日阅读验证记录](docs/verification/2026-10-28-daily-reading.md)。

## 拼写修正

新收录时，在同一次 AI 请求里检查拼写并生成完整笔记。明确且唯一的错拼会自动修正，例如 `introdce → introduce`，文件名、标题、例句及词条关联统一使用 `introduce`，输入框和状态栏会显示结果。词卡保留简短修正说明，原输入写在 `original_input` 属性中；遇见时的原句保留原文。

`introduced`、`running`、`smaller` 等正确词形继续单独收录，原形写在词形说明中。候选不确定时提示最多三个候选并保留输入，不生成任何候选笔记。修正后的词已收录时打开已有词条，不覆盖内容，也不创建错拼文件。取消、保存失败和不一致的模型返回均保留输入。

模型负责拼写判断，本地检查输入回显、修正幅度、词形关系、例句中的目标词及文件名一致性；没有新增联网词典、第二次模型调用或自动纠错重试。当前配置单次对比中，旧版约 2.49 秒，新版正常词约 2.29 秒，新版纠错加整理约 2.51 秒；这是定点样本，实际受服务端与网络影响。完整验收见[拼写修正验证记录](docs/verification/2026-10-28-spelling-correction.md)。

已有词条仍直接打开，不重新调用 AI；本功能不会批量改写、重命名或重新解析历史笔记。旧接口若拒绝无效词仍可安全提示，但成功响应必须返回新增的拼写判断字段，缺失时停止保存。

## 生成失败与本地诊断

已修复原形动词例句使用正常第三人称时被误拒的问题，例如 `produce` 的例句出现 `produces`、`credit` 的动词义项例句出现 `credits`。卡片标题、文件名和输入词不变，例句保留原文并正确加粗实际出现的词形。仅在输入词等于可靠原形且解析含动词义项时接受保守三单；正确的 `introduced` 等词形仍单独保存，不将派生词或复合词视作当前词。

格式校验失败会说明具体字段及要求，例如“释义需为1–3项（本次4项）”或“英式音标应为文本”。词性、数量、拼写身份、截断和安全路径要求仍保持，不用增加模型请求或自动重试掩盖问题。

新版会将失败的安全诊断信息保存到 `%LOCALAPPDATA%\VocabCollector\logs\analysis-日期.jsonl`：时间、输入单词、错误代码、字段、约束和可用的数量。不会记录 API Key、请求头、原句或模型全文；成功解析不写日志。日志按日保存，单文件达到256 KiB后轮转，并清理较旧的本工具日志。日志不可写时仍保留原错误和输入。

旧版没有保存失败响应，无法追溯旧提示对应的具体字段。本次用真实返回确认并修复了 `produce/produces` 误拒；`credit` 当次受控请求通过，不能据此推断用户之前失败的具体原因。记录与回放验收见[生成修复验证记录](docs/verification/2026-10-28-analysis-failures.md)。

## API 配置

使用 OpenAI 兼容的 **Chat Completions** 接口，示例：

```text
API 地址：https://your-provider.example/v1
API Key：你的服务商提供的 Key
模型名：服务商实际提供的模型名称
```

程序会追加 `/chat/completions`；也可填写已经含此后缀的完整地址。不会猜测或追加 `/v1`。支持 HTTP 和 HTTPS，包括本机地址、局域网 IP 和自定义主机名，例如 `http://localhost:11434/v1`、`http://192.168.1.100:1234/v1`。模型需要能按提示返回 JSON；不要求专有结构化输出功能。

解析最长等待 90 秒，可主动取消。默认请求流式内容，收到正文后显示“AI 正在生成笔记内容…”，完整校验后才生成笔记；也兼容直接返回普通 JSON 的接口。仅当接口用 HTTP 400/422 明确表示不支持 `stream` 时，回退一次非流式请求；其他失败不自动重试。用户点击解析会调用其配置的服务商，具体费用由该服务商和模型决定。

## 笔记与词条关联

笔记沿用用户示例的结构：标题、英美音标、词根、简短中文释义、必要的词形说明、2 个双语例句、常见搭配、语义关系（近义词／反义词）、语法信息（句法模式），最后保留可选的来源原句和独立的“我的笔记”。模型生成内容的规则是：

- 释义 1–3 个，优先当前语境和常见用法；每个义项在引用块中单独一行，与截图中的竖排结构一致。音标对应实际输入词形，不确定时显示未提供。
- 词根放在发音下面，最多 3 组，简短解释可靠的词源和常见变体；与原形、时态词形分开。不可靠时写“暂无可靠词根信息”，不按拼写硬拆。旧接口省略词根字段仍可生成笔记。
- 例句恰好 2 个，优先 6–16 个英文词、最多 20 个，配直白自然的中文。
- 常见搭配通常 3 条（兼容旧接口的 2–4 条），使用完整可用的结构。
- 近义词最多 3 个，反义词最多 2 个，逐项解释适用义项、场景和差异；不为数量编造反义词。
- 句法模式 1–3 条，按词性讲最实用的规则：动词的宾语／介词、名词的可数性／单复数、形容词的修饰／比较形式、副词的位置等。兼容旧响应，未提供语法时明确说明。

模板内容规则见[模板实施计划](docs/superpowers/plans/2026-10-21-template-and-local-links.md)，当前不含程序标签的补链机制见[干净笔记修复验收](docs/verification/2026-10-21-clean-notes.md)。原设计和内嵌注释方案保留为历史记录，不作为当前输出要求。

完整排版预览见 [introduced.md](docs/examples/introduced.md)。此示例由实际渲染器在隔离词库生成，未覆盖用户原文件；音标、词形和主要用法核对 [Oxford introduce](https://www.oxfordlearnersdictionaries.com/us/definition/english/introduce)，例句自拟。内部跳转及反向关联使用 [Obsidian 内部链接](https://obsidian.md/help/links)。

默认路径示例：

```text
你的仓库/
  英语单词/
    名词/resilience.md
    形容词/resilient.md
    词根/duc.md
```

- 一个输入词一份笔记，多种词性写在同一文件内；原句帮助确定归档的主要词性。
- 查重不区分大小写，覆盖单词目录中的普通子目录。重复词只提供已有路径，不调用 AI，不覆盖手写内容。
- 保留输入词形，例如 `running` 和 `run` 分别保存，`saw` 不会自动合并到 `see`。
- Windows 保留设备名 `con/aux/prn/nul` 使用 `_con.md` 等安全文件名，程序仍按原单词查重和关联。
- 历史词条以 **单词目录中的 `.md` 文件名** 识别，不解析任意别名，也不机械删除 `s/ed` 猜原形。词形说明只帮助学习，不改变词条身份。
- AI 给出近义词、反义词及可选的同根词／易混词，未收录的候选仍以普通文字显示，保留学习内容。
- 例句只链接实际存在且唯一匹配的完整单词，忽略大小写。每句最多 3 个不同目标，跳过当前词及常见功能词，同一目标在一句内只链接一次。
- 内部链接示例：`[[英语单词/名词/policy|policy]]`，可供 Obsidian 显示反向链接及图谱。同名多份笔记时不猜目标。
- “词形”段落中的已收录原形和其他词形也会自动链接，例如 `introduced是[[动词/introduce|introduce]]的过去式和过去分词`，中英文紧邻不影响识别。这里只匹配文中实际出现的完整单词，不依靠去掉 `ed` 等方式猜原形；`be`、`have` 等在词形说明中可以链接。
- 程序自动检查单词目录到配置根目录之间最近的 `.obsidian` 仓库标记，生成相对于实际 Obsidian 仓库的路径。例如把“英语单词”本身作为 Obsidian 仓库打开时，使用 `[[动词/introduce|introduce]]`，不重复添加“英语单词”。原来的保存位置及保护记录身份保持稳定。
- 词根卡片单独放在**单词目录内的 `词根` 文件夹**，以单个词根命名，如 `duc.md` 或 `-duc-.md`。`duc / duct（引导）` 这一组的任一变体有唯一卡片时，整组显示成 `[[英语单词/词根/duc|duc / duct]]（引导）`。该组匹配多份不同卡片时保留普通文字；普通单词目录的同名词不会被当成词根。卡片内容可以自由撰写，程序只识别文件名。
- 保存新词后，自动为相关旧例句、近反义词等补链；启动工具或点击右上角“刷新词条链接”，也可处理在 Obsidian 中另行新增的卡片。删除、移动、出现同名歧义时，刷新会移除旧链接或使用新的唯一实际路径。工具关闭时不在后台改写文件，下次启动或刷新再处理。
- 自动补链只处理程序已登记的例句／语义关系／词根／词形区域，校验记录保存在单词目录下 `.vocabcollector/`，不在 Markdown 正文中放程序标记或校验码。人工改过的区域跳过，个人笔记区可自由补充。没有卡片时显示普通文字，不预建空白卡片。以后新增词根卡片，同样可通过启动、保存新词或“刷新词条链接”给已有词根段落补链。较旧笔记没有登记词形区域时，刷新不会擅自接管；本次用户明确指出的 `introduced` 已单独备份、补链并登记，其他段落保持原校验记录。
- 刷新时自动迁移上一版带 `vocabcollector` 管理注释的笔记：先备份和登记补链记录，再去除这些程序注释，保留原有正文和链接。旧的人工笔记不会被自动接管。
- 更新历史笔记前保存原文备份到 `.vocabcollector/backups/`（`.bak` 文件）。`note-state.json` 持久保存自动补链的区域记录，请随词库保留；`link-index.json` 只缓存时间和引用关系，损坏或丢失可重建。持久记录丢失时，干净的 Markdown 仍可正常阅读，但未登记旧笔记不会被擅自改写。
- 手动移动一份已登记笔记后，它仍可作为链接目标，但当前版本暂停自动改写这份笔记本身，防止把相同文件名的私人笔记误认成原文件。
- 单词输出子目录避开 `# ^ [ ] |` 等 Wikilink 保留字符；旧子目录包含这些字符时仍查重，但跳过关联。仓库根目录可以包含 Windows 允许的特殊字符，打开时会编码。
- 为防止写到仓库外，不跟随目录链接、junction 或文件 symlink。请选择普通本地文件夹；首次使用请确认路径。

新建 Markdown 使用 UTF-8 与 LF，通过临时文件和原子移动提交；重复单词不会覆盖。历史自动补链使用原子替换并留备份。`.vocabcollector.write.lock` 是程序用于协调并发保存与补链的空锁文件，不是笔记。

## 词库规模与 token

每次生成只发送固定的内容规则、当前单词和可选原句。**历史词库不发送给模型**；词条从几十个增加到几万个，不会因为历史数量增加而加长请求。新增语法和关系说明会让每份笔记的输出比初版略长，实际 token 取决于输入、模型及输出内容。

链接查找、历史补链和手动刷新完全在本地完成，额外模型 token 为 0。词库扩大主要增加首次索引和本地文件处理时间。

本版精简模型提示词和解释长度，保留学习所需字段；仅对 DeepSeek 官方 HTTPS 接口的 `deepseek-flash`、`deepseek-v4-pro` 使用[文档支持的非思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)，其他接口不添加该专用参数。本地扫描跳过 `.obsidian`、`.vocabcollector` 等内部目录，保存时复用已有索引并保留提交前的加锁复查。流式反馈可以更早确认服务端正在生成；总耗时仍受模型速度、输出长度和网络影响。新模板用于新生成的词卡，已有人工整理笔记不会自动重排或重新调用模型。

## 验证与构建

开发需要 Windows x64 和 .NET 10 SDK。仓库已提交 NuGet 锁文件。

```powershell
pwsh -NoProfile -File scripts/verify.ps1
pwsh -NoProfile -File scripts/publish.ps1
```
