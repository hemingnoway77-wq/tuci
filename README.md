# 兔词

兔词把遇到的英文单词生成 Markdown 笔记。Windows 和 iPhone 均可在应用内阅读、查看简卡和漫游复习，两端可自动同步。Windows 新安装使用应用管理的本地词库，已有 Markdown 或 Obsidian 词库也可原样沿用。

- [iPhone 构建、真机安装与使用](ios/README.md)
- [私人词库同步服务部署](server/README.md)

下文介绍 Windows 桌面版。

## 开始使用

1. 完整解压 Windows 发布 ZIP，保留 `Assets` 目录，再双击 `兔词.exe`（本地构建默认为 `dist/win-x64/兔词.exe`）。发布版自带 .NET 和离线英译中语言包，无需另装 .NET、Python、Node.js 或 Firefox。
2. 顶部提供「收录 / 词库 / 漫游 / 每日阅读」四个入口，所有页面共用相同导航和主题。初次使用会在 `%LOCALAPPDATA%\VocabCollector\library\英语单词` 建立本地词库，无需安装或启动 Obsidian。
3. 阅读已有笔记、导入 Markdown、漫游复习和获取每日阅读都不需要 API 配置。可先进入「词库」，点击“导入 Markdown”选择已有笔记。
4. 生成新词卡前，点击右上角“设置”，填写 API 地址、API Key 和模型名。可更改“本地词库位置”和“单词保存子目录”（默认 `英语单词`），按需开启“按主要词性分文件夹”。
5. 在「收录」粘贴一个单词；可附上遇见它时的原句。点击“解析并保存”，完成后直接阅读整篇笔记。遇到已有词也会读取已有内容，不重新调用模型。
6. 在「词库」从左侧文件列表选择笔记，右侧直接展示 Markdown；单击关联词在同一阅读区跳转，前进／后退保留位置。鼠标悬停关联词即可查看简卡。在「漫游」可阅读词卡、切换下一张或标记“今天已记住”。

已有版本保存过的词库位置会继续使用，不自动搬迁、删除或重排笔记。需要沿用 Obsidian 词库时，在设置中选择原来的根目录和单词子目录即可；原有 API、主题和阅读缓存设置继续保留。

从文章收录时自动带入的原句只关联当前词；在主收录或阅读侧栏换成另一个词后，旧自动原句会清空。仅改大小写、外侧空白或等价撇号，以及保存时的自动拼写纠正，仍保留对应原句。手动修改过的原句按用户输入保留。

## 界面与阅读预览

四个页面统一采用兔词的纸页式排版和墨白／暖灰／玫红主题。词库只保留左侧文件列表与右侧 Markdown 展示，顶部导航、主题按钮和底部状态栏始终与其他页面一致。顶部导航共用一条短线，切换时先伸长再收拢，模块使用轻微淡入和侧移。文件列表可以调宽、收起和恢复；收展使用短暂的静态画面过渡，正文只按最终宽度排版一次。切换笔记直接更新正文，不再移动整张阅读卡。系统关闭动画时直接显示终态，正文不做缩放。

启动时先显示简洁的准备界面，载入本地词库及学习记录，并在遮罩下面完成文件行、控件模板和首次布局，让第一次进入词库也能快速响应。重复进入模块共用加载任务和短时快照；文件变化及手动刷新会绕过快照重新读取，切回窗口不再无条件重复扫描。准备期间不选择笔记、不抽取漫游词、不计复习次数，也不获取文章或启动翻译模型。验收见[加载与流畅切换记录](docs/verification/2026-11-06-fluid-navigation.md)及[首次使用细节修正](docs/verification/2026-11-06-first-use-polish.md)。

小型中文标签、按钮、路径与说明使用清晰的系统界面字体；词库正文为 16 DIP，并提供中文回退。辅助文字至少 12 DIP，其他页面输入和正文 14 DIP，保留布局取整、Display 格式化和 ClearType。

所有页面的主题选择统一保存在 `%LOCALAPPDATA%\VocabCollector\appearance.json`。切换保留当前输入和阅读内容，不调用 AI；标题栏同样跟随主题。词库不会读取旧工作区的深色／隐藏导航偏好。偏好保存失败时会提示，仍可使用当前界面。

图标采用用户最终确认的透明黑色兔耳放大镜：黑色轮廓，外围及镜圈内部保留真实透明通道。exe、窗口标题栏、任务栏和界面左上角品牌标记统一使用同一图标；提供 16–256 像素的多尺寸版本。验收见[图标与字体清晰度验证记录](docs/verification/2026-11-04-icon-and-legibility.md)，原界面改版见[书页界面验证记录](docs/verification/2026-11-04-literary-redesign.md)。

笔记使用本地原生文档排版：隐藏 YAML 属性、Markdown 格式符号和程序注释，展示标题、分行释义、加粗、引用、列表及词条关联。正文与标题使用无衬线字体，引用中的每行释义保持分行，文字与重点色跟随当前主题。选择复制获得阅读文字；文件仍是普通 Markdown。词库正文的内部链接在同一阅读区导航，普通悬停显示不抢焦点的浮动简卡，不再显示黑底文件路径。移开、换文或离页会关闭简卡。同名目标会列出候选，缺失目标显示提示，带目录的链接不会误跳到其他目录的同名笔记。前进／返回恢复对应笔记和阅读位置。HTTP/HTTPS 链接在应用内的来源文章窗口打开。点击导航上方或其他非交互空白可移走输入光标，不影响按钮、链接或正文选择。

滚动条闲置时隐藏，实际滚动、拖动或鼠标移到滚动条区域时淡入细窄的半透明滑块；停止后约一秒淡出，仍保留足够的拖动区域。原句、设置、预览和词条列表使用同一套滚动样式。滚轮采用约 90 毫秒的短缓动，拖动、键盘和阅读定位保持直接响应，按行滚动的列表保留原生行为。每日阅读正文的滚动条放在视口最右侧，与文字保留间距；打开文章使用轻微侧移与淡入。窗口最小为 920×700，较小窗口内可滚动查看输入与笔记。

Markdown 笔记阅读、漫游和每日纯净正文阅读不需要浏览器组件，也不加载笔记中的远程图片。Markdown 解析使用 Markdig，文章正文提取使用 AngleSharp；离线翻译和可选的来源网页使用 Microsoft Edge WebView2。第三方声明随发布附带并嵌入程序。早期预览的实现与验收见[粉色界面验证记录](docs/verification/2026-10-22-pink-interface.md)。

可以把发布目录复制到别处运行，并保留随附文件和第三方声明。设置位于 `%LOCALAPPDATA%\VocabCollector\settings.json`，API Key 使用当前 Windows 用户的 DPAPI 加密，不以明文保存。把此配置文件复制到其他电脑或其他 Windows 账户后，需要重新填写 Key。

## 词库与漫游

词库、笔记预览和来源网页的前进／后退使用统一细线图标，文件列表展开／收起也使用侧栏图标；悬停可查看名称，并保留键盘和无障碍操作。刷新按钮获得鼠标焦点时不增加边框或改变高度，键盘操作仍有轻量焦点提示。

原句归属、稳定刷新、导航图标和横向细纹磨砂的验收见[交互与横向磨砂优化记录](docs/verification/2026-11-06-capture-library-roaming-polish.md)。

「词库」读取单词目录中的 Markdown，包括普通中文笔记和词根，文件／文件夹共用一棵树。可展开目录、搜索标题和正文、选择文件阅读、导入和刷新。只有文件保留选中底色；目录行的悬停反馈不会跟随子文件一起出现。右侧显示完整排版正文、当前路径及前进／后退，保留阅读位置和文字选择。

按此次需求，词库界面收敛为两栏阅读，原先的多标签、源码编辑、图谱、独立右栏与局部黑色主题没有界面入口。已有 Markdown、学习记录及旧工作区元数据保留，原文不会因为切换界面而被改写。

“导入 Markdown”可多选 `.md`，复制到单词目录根层，源文件保留；目标同名不覆盖。外部文件变化后刷新，目录扫描、解析和导入拒绝越界及文件／目录链接。刷新保留用户展开状态和当前阅读内容，不重新调用 AI。

「漫游」仅从英文词条中抽取，词根和普通中文说明可阅读但不参与抽取。权重与 iPhone 一致：

```text
0.5 + 3*ln(1+间隔天数) + exp(-入库天数/3)
    + 2*(1-(记住次数+1)/(记住次数+跳过次数+2)) + min(跳过次数,3)/3
```

间隔天数取距上次实际展示的连续秒数除以 86400；未展示过时从入库时间起算。入库时间优先读取笔记的 `created` 属性。入库天数同样按连续秒数计算，记住／跳过次数按电脑本地日期重置。记住后仍可能再次抽中，不强行排除当天看过的词。

每张实际展示的卡片生成一次展示记录；“下一张”计跳过，“今天已记住”计记住，同一次展示只能完成一次。查看简卡、打开全文、返回或重绘不会增加次数。复习记录原子保存，保存失败时保留当前卡片，提示重试；跨日保留入库和上次展示时间。

释义以柔和的横向细纹磨砂遮蔽，像墨色沿左右化开，没有边框或可见提示。模糊区域预留光晕，原文仍与单词对齐。按住释义区域会在约 120 毫秒内平滑清晰，松开后约 100 毫秒恢复遮蔽；聚焦该区域后也可按住空格查看。换词、离页、窗口失活或捕获丢失都会立即停止显影并重新遮住答案，关闭系统动画时直接切换终态。纹理静止不闪动，单词和音标保持清晰；不支持着色器时保留较强的高斯模糊。“阅读整篇笔记”在漫游右侧展开第三栏，可浏览关联词并使用前进／后退图标，也可用右上角细线 X 单独关闭；不会切走漫游或额外记一次复习，继续抽词时开启中的预览会跟随当前词更新。

右侧状态栏以条形显示抽取时的相对权重，不展示数值。复习覆盖支持本周／本月切换，按当前英文词库中遇见过的不同单词去重，例如 100 个词遇见过 50 个即为一半。自然周从周一开始，自然月从每月 1 日开始，按本机本地日期统计。

漫游页保留标题、数据和操作，去掉装饰口号与功能说明。状态栏不滚动，按内容实际高度从下依次隐藏每日漫游、复习覆盖；拉高后恢复，已选周期保留。周／月共用一条短细淡线，切换时先向目标伸长、再收拢；系统关闭动画时直接落到目标。验收见[漫游精简与弹性布局](docs/verification/2026-11-06-roaming-minimal.md)。

每日活动展示最近 12 周，每格一天，次数越多颜色越深；悬停显示日期、实际漫游次数和不同单词数。恢复原卡、查看释义、读整篇笔记不增加次数。详细活动保留最近 400 天，与曝光记录一同原子保存。旧版未保存完整每日历史，统计从新版开始累计，保留原有权重及记住／略过记录。后台同步与扫描不再反复禁用漫游按钮，实际推进期间仍防止重复点击。验收见[漫游状态与按住回想](docs/verification/2026-11-06-roaming-dashboard.md)。

索引和复习记录按词库隔离，保存在 `%LOCALAPPDATA%\VocabCollector\library-catalog\<词库标识>\`，不写入 Markdown 正文，也不上传同步。唯一且内容未变的重命名会保留本机学习身份；内容相同的多个候选不会被擅自合并。学习状态只属于本机，Windows 与 iPhone 的 Markdown 同步不会合并两端的学习进度。

## 每日阅读

点击主窗口顶部的「每日阅读」，即可在同一窗口内看到最多两篇通用英文泛读和一篇技术文章。每篇文章展示英文标题、摘要、来源及可用的发布日期，点击标题或“阅读全文”在当前模块打开纯净全文；可选“来源网页”在独立文章窗口查看网站。无需配置 API Key 或 Obsidian；整理单词时也可以暂时切到阅读页。

来源文章窗口只接受不含登录凭据的 HTTP/HTTPS 地址，使用独立的 `%LOCALAPPDATA%\VocabCollector\browser` 浏览器数据目录。网页需要 Microsoft Edge WebView2 Runtime；发布包包含 SDK 控件和加载器，不附带浏览器运行时。缺少运行时时会提示安装，可从 [Microsoft 官方下载页](https://developer.microsoft.com/en-us/microsoft-edge/webview2/) 安装后重试；这不影响 Markdown 阅读和漫游。

文章来自公开订阅源：ScienceDaily 社会／环境、Cloudflare 技术博客和 BBC Technology。它们是泛读材料，不是考研真题或配套试题。目录顶部提供「刷新文章」，不再显示右侧介绍卡。点击标题或「阅读全文」后，在当前模块加载来源正文并清除广告、脚本与导航；点击「返回每日阅读」恢复原目录位置。可选「来源网页」保留网页查看入口。

同一天重开优先使用当日缓存，跨日获取来源并尽量轮换推荐；“刷新文章”可手动重新获取。日期按电脑本地日期计算；关闭程序后不在后台推送。切换到其他页面会取消正在进行的获取，已经加载的文章会保留，返回后继续阅读。网络不通时保留上次缓存并说明状态，首次使用且无缓存时可重试。文章的发布日期和当天推荐日期分别显示，不把旧文章标为新发布。

**每日阅读额外 AI token 为 0。** 获取文章、每日选择、正文清洗和缓存不调用模型，不读取或匹配本地单词库，也不写入笔记。纯净正文以原生可选择文字显示，不加载网页广告或远程脚本。正文缓存独立保存在 `%LOCALAPPDATA%\VocabCollector\reading\articles`，不包含 API Key；已有缓存可离线阅读，来源失败会说明状态，无全文时不会拿摘要冒充全文。离开阅读页会取消正在进行的获取和翻译，已载入的文章与位置保留。

点选正文中的英文词会出现「翻译／收录」。点击翻译后，优先查询安装包自带的 ECDICT 离线英汉词典，在原生浮窗中展示音标、不同词性的中文释义及词典提供的原形。使用完整基础库筛选出的约 40 万个符合应用单词格式的词条，保留源释义和词性，不用机器翻译猜词性。切换单词会清空上一次的详情；较长释义可在小卡片内滚动。

词典没有收录的词才使用自带的 Mozilla Firefox/Bergamot 英译简中模型，在本机计算并显示普通译文。两条路径均不需要翻译 API Key、额度或额外语言包下载，不把单词、原句、文章或 AI Key 发给翻译服务器。词典命中时不启动模型；模型延迟到首次需要时启动，使用独立的 `%LOCALAPPDATA%\VocabCollector\offline-translation-browser` 本地运行目录。词典、模型和引擎的固定来源、SHA-256 和完整许可位于 `Assets/OfflineDictionary` 与 `Assets/OfflineTranslation`，构建与发布无需下载数据。完整解压发布 ZIP 并保留整个 `Assets` 目录后运行 `兔词.exe`。模型回退使用系统的 WebView2 Runtime；Windows 11 通常已预装，缺少时会明确提示安装，离线词典、Markdown、漫游和纯净正文阅读仍可使用。词典和机器翻译均可能有缺失或误译；没有来源数据的字段不显示。

离线词典与翻译的真实数据、界面及发布包验收见[离线词典与翻译验证记录](docs/verification/2026-11-06-offline-translation.md)。

收录会保留当前词形，把所在原句预填到文章右侧可关闭的收录面板；可以编辑，在面板中点击「解析并保存」后才调用原有 AI 并写入词库，生成结果就地预览。关闭、离页或切换文章会取消面板发起的未完成请求，已保存的笔记保留。文章位置保留，不切换收录导航。选择文字仍可复制，也可选择单个词后按 Enter 打开词操作。验收见[阅读点击与侧栏收录](docs/verification/2026-11-06-reading-capture-pane.md)，前版见[纯净阅读与词库调整记录](docs/verification/2026-11-06-pure-reading.md)。

## 拼写修正

新收录时，在同一次 AI 请求里检查拼写并生成完整笔记。明确且唯一的错拼会自动修正，例如 `introdce → introduce`，文件名、标题、例句及词条关联统一使用 `introduce`，输入框和状态栏会显示结果。词卡保留简短修正说明，原输入写在 `original_input` 属性中；遇见时的原句保留原文。

`introduced`、`running`、`smaller` 等正确词形继续单独收录，原形写在词形说明中。候选不确定时提示最多三个候选并保留输入，不生成任何候选笔记。修正后的词已收录时打开已有词条，不覆盖内容，也不创建错拼文件。取消、保存失败和不一致的模型返回均保留输入。

模型负责拼写判断，本地检查输入回显、修正幅度、词形关系、例句中的目标词及文件名一致性；没有新增联网词典、第二次模型调用或自动纠错重试。当前配置单次对比中，旧版约 2.49 秒，新版正常词约 2.29 秒，新版纠错加整理约 2.51 秒；这是定点样本，实际受服务端与网络影响。完整验收见[拼写修正验证记录](docs/verification/2026-10-28-spelling-correction.md)。

已有词条仍直接打开，不重新调用 AI；本功能不会批量改写、重命名或重新解析历史笔记。旧接口若拒绝无效词仍可安全提示，但成功响应必须返回新增的拼写判断字段，缺失时停止保存。

## 生成失败与本地诊断

已修复原形动词例句使用正常第三人称时被误拒的问题，例如 `produce` 的例句出现 `produces`、`credit` 的动词义项例句出现 `credits`。卡片标题、文件名和输入词不变，例句保留原文并正确加粗实际出现的词形。仅在输入词等于可靠原形且解析含动词义项时接受保守三单；正确的 `introduced` 等词形仍单独保存，不将派生词或复合词视作当前词。

格式校验失败会说明具体字段及要求，例如“释义需为1–3项（本次4项）”或“英式音标应为文本”。词性、数量、拼写身份、截断和安全路径要求仍保持，不用增加模型请求或自动重试掩盖问题。

新版会将失败的安全诊断信息保存到 `%LOCALAPPDATA%\VocabCollector\logs\analysis-日期.jsonl`：时间、输入单词、错误代码、字段、约束和可用的数量。不会记录 API Key、请求头、原句或模型全文；成功解析不写日志。日志按日保存，单文件达到256 KiB后轮转，并清理较旧的本工具日志。日志不可写时仍保留原错误和输入。

旧版没有保存失败响应，无法追溯旧提示对应的具体字段。本次用真实返回确认并修复了 `produce/produces` 误拒；`credit` 当次受控请求通过，不能据此推断用户之前失败的具体原因。记录与回放验收见[生成修复验证记录](docs/verification/2026-10-28-analysis-failures.md)。

## API 配置

使用 OpenAI 兼容的 **Chat Completions** 接口，示例：

```text
API 地址：https://your-provider.example/v1
API Key：你的服务商提供的 Key
模型名：服务商实际提供的模型名称
```

程序会追加 `/chat/completions`；也可填写已经含此后缀的完整地址。不会猜测或追加 `/v1`。支持 HTTP 和 HTTPS，包括本机地址、局域网 IP 和自定义主机名，例如 `http://localhost:11434/v1`、`http://192.168.1.100:1234/v1`。模型需要能按提示返回 JSON；不要求专有结构化输出功能。

解析最长等待 90 秒，可主动取消。默认请求流式内容，收到正文后显示“AI 正在生成笔记内容…”，完整校验后才生成笔记；也兼容直接返回普通 JSON 的接口。仅当接口用 HTTP 400/422 明确表示不支持 `stream` 时，回退一次非流式请求；其他失败不自动重试。用户点击解析会调用其配置的服务商，具体费用由该服务商和模型决定。

## 笔记与词条关联

笔记沿用用户示例的结构：标题、英美音标、词根、简短中文释义、必要的词形说明、2 个双语例句、常见搭配、语义关系（近义词／反义词）、语法信息（句法模式），最后保留可选的来源原句和独立的“我的笔记”。模型生成内容的规则是：

- 释义 1–3 个，优先当前语境和常见用法；每个义项在引用块中单独一行，与截图中的竖排结构一致。音标对应实际输入词形，不确定时显示未提供。
- 词根放在发音下面，最多 3 组，简短解释可靠的词源和常见变体；与原形、时态词形分开。不可靠时写“暂无可靠词根信息”，不按拼写硬拆。旧接口省略词根字段仍可生成笔记。
- 例句恰好 2 个，优先 6–16 个英文词、最多 20 个，配直白自然的中文。
- 常见搭配通常 3 条（兼容旧接口的 2–4 条），使用完整可用的结构。
- 近义词最多 3 个，反义词最多 2 个，逐项解释适用义项、场景和差异；不为数量编造反义词。
- 句法模式 1–3 条，按词性讲最实用的规则：动词的宾语／介词、名词的可数性／单复数、形容词的修饰／比较形式、副词的位置等。兼容旧响应，未提供语法时明确说明。

模板内容规则见[模板实施计划](docs/superpowers/plans/2026-10-21-template-and-local-links.md)，当前不含程序标签的补链机制见[干净笔记修复验收](docs/verification/2026-10-21-clean-notes.md)。原设计和内嵌注释方案保留为历史记录，不作为当前输出要求。

完整排版预览见 [introduced.md](docs/examples/introduced.md)。此示例由实际渲染器在隔离词库生成，未覆盖用户原文件；音标、词形和主要用法核对 [Oxford introduce](https://www.oxfordlearnersdictionaries.com/us/definition/english/introduce)，例句自拟。内部跳转及反向关联使用 [Obsidian 内部链接](https://obsidian.md/help/links)。

默认路径示例：

```text
本地词库或已有仓库/
  英语单词/
    名词/resilience.md
    形容词/resilient.md
    词根/duc.md
```

- 一个输入词一份笔记，多种词性写在同一文件内；原句帮助确定归档的主要词性。
- 查重不区分大小写，覆盖单词目录中的普通子目录。重复词在应用内读取已有全文，不调用 AI，不覆盖手写内容；同名多份时可选择要阅读的笔记。
- 保留输入词形，例如 `running` 和 `run` 分别保存，`saw` 不会自动合并到 `see`。
- Windows 保留设备名 `con/aux/prn/nul` 使用 `_con.md` 等安全文件名，程序仍按原单词查重和关联。
- 历史词条以 **单词目录中的 `.md` 文件名** 识别，不解析任意别名，也不机械删除 `s/ed` 猜原形。词形说明只帮助学习，不改变词条身份。
- AI 给出近义词、反义词及可选的同根词／易混词，未收录的候选仍以普通文字显示，保留学习内容。
- 例句只链接实际存在且唯一匹配的完整单词，忽略大小写。每句最多 3 个不同目标，跳过当前词及常见功能词，同一目标在一句内只链接一次。
- 内部链接示例：`[[英语单词/名词/policy|policy]]`，可供 Obsidian 显示反向链接及图谱。同名多份笔记时不猜目标。
- “词形”段落中的已收录原形和其他词形也会自动链接，例如 `introduced是[[动词/introduce|introduce]]的过去式和过去分词`，中英文紧邻不影响识别。这里只匹配文中实际出现的完整单词，不依靠去掉 `ed` 等方式猜原形；`be`、`have` 等在词形说明中可以链接。
- 程序自动检查单词目录到配置根目录之间最近的 `.obsidian` 仓库标记，生成相对于实际 Obsidian 仓库的路径。例如把“英语单词”本身作为 Obsidian 仓库打开时，使用 `[[动词/introduce|introduce]]`，不重复添加“英语单词”。原来的保存位置及保护记录身份保持稳定。
- 词根卡片单独放在**单词目录内的 `词根` 文件夹**，以单个词根命名，如 `duc.md` 或 `-duc-.md`。`duc / duct（引导）` 这一组的任一变体有唯一卡片时，整组显示成 `[[英语单词/词根/duc|duc / duct]]（引导）`。该组匹配多份不同卡片时保留普通文字；普通单词目录的同名词不会被当成词根。卡片内容可以自由撰写，程序只识别文件名。
- 保存新词后，自动为相关旧例句、近反义词等补链；启动工具或点击右上角“刷新词条链接”，也可处理在 Obsidian 中另行新增的卡片。删除、移动、出现同名歧义时，刷新会移除旧链接或使用新的唯一实际路径。工具关闭时不在后台改写文件，下次启动或刷新再处理。
- 自动补链只处理程序已登记的例句／语义关系／词根／词形区域，校验记录保存在单词目录下 `.vocabcollector/`，不在 Markdown 正文中放程序标记或校验码。人工改过的区域跳过，个人笔记区可自由补充。没有卡片时显示普通文字，不预建空白卡片。以后新增词根卡片，同样可通过启动、保存新词或“刷新词条链接”给已有词根段落补链。较旧笔记没有登记词形区域时，刷新不会擅自接管；本次用户明确指出的 `introduced` 已单独备份、补链并登记，其他段落保持原校验记录。
- 刷新时自动迁移上一版带 `vocabcollector` 管理注释的笔记：先备份和登记补链记录，再去除这些程序注释，保留原有正文和链接。旧的人工笔记不会被自动接管。
- 更新历史笔记前保存原文备份到 `.vocabcollector/backups/`（`.bak` 文件）。`note-state.json` 持久保存自动补链的区域记录，请随词库保留；`link-index.json` 只缓存时间和引用关系，损坏或丢失可重建。持久记录丢失时，干净的 Markdown 仍可正常阅读，但未登记旧笔记不会被擅自改写。
- 手动移动一份已登记笔记后，它仍可作为链接目标，但当前版本暂停自动改写这份笔记本身，防止把相同文件名的私人笔记误认成原文件。
- 单词输出子目录避开 `# ^ [ ] |` 等 Wikilink 保留字符；旧子目录包含这些字符时仍查重，但跳过关联。仓库根目录可以包含 Windows 允许的特殊字符，打开时会编码。
- 为防止写到仓库外，不跟随目录链接、junction 或文件 symlink。请选择普通本地文件夹；首次使用请确认路径。

新建 Markdown 使用 UTF-8 与 LF，通过临时文件和原子移动提交；重复单词不会覆盖。历史自动补链使用原子替换并留备份。`.vocabcollector.write.lock` 是程序用于协调并发保存与补链的空锁文件，不是笔记。

## 词库规模与 token

每次生成只发送固定的内容规则、当前单词和可选原句。**历史词库不发送给模型**；词条从几十个增加到几万个，不会因为历史数量增加而加长请求。新增语法和关系说明会让每份笔记的输出比初版略长，实际 token 取决于输入、模型及输出内容。

链接查找、历史补链和手动刷新完全在本地完成，额外模型 token 为 0。词库扩大主要增加首次索引和本地文件处理时间。

本版精简模型提示词和解释长度，保留学习所需字段；仅对 DeepSeek 官方 HTTPS 接口的 `deepseek-flash`、`deepseek-v4-pro` 使用[文档支持的非思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)，其他接口不添加该专用参数。本地扫描跳过 `.obsidian`、`.vocabcollector` 等内部目录，保存时复用已有索引并保留提交前的加锁复查。流式反馈可以更早确认服务端正在生成；总耗时仍受模型速度、输出长度和网络影响。新模板用于新生成的词卡，已有人工整理笔记不会自动重排或重新调用模型。
